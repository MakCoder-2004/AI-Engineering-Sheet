The Journey at a Glance

A 21-phase curriculum built for self-study — roughly 6–9 months part-time or 3–4 months full-time. The core track (Phases 0–8) gets you building; the advanced track (violet accents) is what separates a practitioner from a senior AI engineer: context engineering, durable orchestration, inference optimization, post-training, and security.

One honest warning

This field moves fast — MCP didn't exist before late 2024, "context engineering" only became a named discipline in 2025, and reasoning models rewrote the rules of test-time compute. The durable foundation is the concepts: transformers, RAG, the ReAct loop, the agent-harness idea, durable execution. Expect to re-check the specific tool landscape every few months via each project's official docs.

3 Phase 3 · Representation

Embeddings

An embedding is a numerical vector that represents the meaning of text — semantically similar text produces vectors close together in vector space. The foundation of semantic search, RAG, and recommendations.

4 Phase 4 · Storage

Vector Databases

Once you have thousands of embeddings, brute-force similarity search doesn't scale — you need a database built for Approximate Nearest Neighbor (ANN) search. Pick based on your scale and infrastructure taste.

Difficulty · medium Prereqs · Phase 3 ≈ 1 week
0/8 ticked complete ✓

Hands-on tasks

  • Spin up Chroma locally with Docker, insert 1,000 vectors, query them
  • Try filtered search — metadata + vector query combined
  • Benchmark Chroma vs Qdrant on the same dataset (latency, recall)
  • Set up pgvector in Postgres, run a hybrid SQL + vector query
5 Phase 5 · Retrieval

Retrieval-Augmented Generation (RAG)

LLMs only know their training data. RAG lets a model answer using your documents by retrieving relevant chunks and inserting them into the prompt. The naive pipeline is simple — production RAG needs more.

Difficulty · medium Prereqs · Phases 3–4 ≈ 2 weeks
0/9 ticked complete ✓

The naive RAG pipeline

  1. Ingest — load PDFs, docs, web pages
  2. Chunk — split documents (size & overlap hugely affect quality)
  3. Embed — turn each chunk into a vector
  4. Store — vectors + text + metadata in a vector DB
  5. Retrieve — embed the query, fetch top-k similar chunks
  6. Augment + Generate — insert chunks into the prompt, answer grounded in context

Study checklist

Frameworks that help

FrameworkFocus
LlamaIndexRAG-first, excellent loaders & indexing
LangChainGeneral LLM toolbox + RAG components
HaystackProduction pipelines, built-in evaluation
VerbaOpen-source RAG UI (Weaviate)

Unstructured, docling and friends are the heavy lifters for the ingest step.

8 Phase 8 · Reasoning loops

AI Agents & the Agent Harness

An agent doesn't just respond once — it reasons, acts (via tools), observes, and repeats until done. That loop is ReAct, and it underlies nearly every agent framework. The "agent harness" is everything around the model that makes it reliable.

Difficulty · medium Prereqs · Phases 1, 2, 7 ≈ 1–2 weeks
0/8 ticked complete ✓

The agent harness

Build a minimal harness

  1. Tool registry: {"search": search_fn, "calc": calc_fn}
  2. Message-history management (system / user / assistant / tool)
  3. Loop with max iterations, error handling, timeout
  4. State persistence: save/load agent state to JSON
  5. A simple guardrail — block rm -rf-style commands

Variants to know: ReAct (interleaved), Plan-and-Execute (plan first), Reflexion (self-critique).

Why it matters

LangGraph, CrewAI, and AutoGen are essentially pre-built harnesses. Understanding the concept lets you know what's happening underneath any framework — and lets you build a custom harness when a framework doesn't fit.

9 Phase 9 · Advanced track

Context Engineering & Agent Memory

Prompt engineering asks "what do I say to the model?" Context engineering asks "what does the model need to see at this exact step — and what should it never see?" It's the discipline of curating the entire context window: system prompts, retrieved chunks, tool output, memory, and history. Frontier labs call this the defining craft of agent development.

Difficulty · hard Advanced track Prereqs · Phases 2, 5, 8 ≈ 1–2 weeks
0/10 ticked complete ✓

Study checklist

Memory & context tooling

ToolApproach
Mem0Drop-in memory layer — extracts, dedupes, and retrieves user facts
ZepTemporal knowledge graph — memory that tracks how facts change over time
LangMemLangGraph-native memory: semantic, episodic, procedural stores
Letta (MemGPT)OS-style memory management — the model pages its own memory
CheckpointersThread-level short-term state (Postgres/Redis) — the "RAM" of your agent

Practice project

  1. Add a long-term memory store (Mem0 or LangMem) to your Phase 8 harness
  2. Implement history compaction — summarize when the thread exceeds a token budget
  3. Cap and reformat tool outputs; watch error recovery improve
  4. Run a needle-in-a-haystack eval at 25% / 50% / 90% context fill — chart the degradation

Read: Anthropic's "Effective context engineering for AI agents" and the "lost in the middle" paper (Liu et al.).

11 Phase 11 · Advanced track

Orchestration & Durable Execution

A while loop around an LLM works on your laptop. Production agents run for minutes or hours, crash mid-task, hit rate limits, and wait on humans. Durable execution means every step is persisted, so a workflow can crash, retry, pause for approval, and resume exactly where it left off. This is the orchestration layer senior engineers reach for.

Difficulty · hard Advanced track Prereqs · Phases 8, 10 ≈ 1–2 weeks
0/10 ticked complete ✓

Study checklist

Orchestration engines

EngineModelFit
TemporalDurable execution via event sourcing + replayLong-running, mission-critical agent workflows
LangGraph PlatformCheckpoints + interrupts, agent-nativeAgent graphs needing pause/resume & HITL
InngestEvent-driven functions with step durabilityServerless teams, webhook/cron-triggered agents
HatchetDistributed task queue with durabilityHigh-throughput background agents
Prefect / DagsterData-pipeline orchestrationBatch & agentic data workflows

Practice project

  1. Pick Temporal (Python SDK) or LangGraph checkpointers
  2. Wrap a multi-step agent; add idempotency keys to every side-effecting tool
  3. Add a human-approval step with a 24h timeout and a safe default action
  4. Kill the worker mid-run — confirm clean resume and a complete audit trail
12 Phase 12 · Interop

Model Context Protocol (MCP) & Interoperability

MCP is the "USB-C for AI" — an open standard (from Anthropic, late 2024, now a Linux Foundation project) for how agents connect to external tools and data. Build one server; any MCP-compatible agent can use it.

16 Phase 16 · Reliability

LLMOps: Evaluation, Monitoring, Fine-Tuning & Guardrails

What separates a weekend demo from something reliable enough to ship. Evaluation, observability, guardrails, fine-tuning, and prompt versioning.

Difficulty · hard Prereqs · Phases 5, 7, 8 ≈ 2 weeks
0/9 ticked complete ✓

Evaluation & observability

Implement these

  • Create an evaluation dataset (20+ Q&A pairs) for your RAG/agent
  • Run Ragas: faithfulness, answer relevancy, context precision
  • Set up LangSmith tracing on your deployed agent
  • Add input/output guardrails — block PII, validate JSON schema
  • Fine-tune a small model with LoRA on your domain data
  • Version prompts in Git; automate evaluation on PR merge

When to fine-tune

Fine-tune only when RAG and prompting aren't enough — tone, format, or domain behavior you can't get from context. Otherwise you're paying for training compute you don't need. Phase 17 goes deeper: DPO, RLVR, and reasoning models. For adversarial testing, see Phase 18.

17 Phase 17 · Advanced track

Post-Training, Alignment & Reasoning Models

Pretraining gives a model knowledge; post-training gives it behavior. This is where SFT, preference tuning (DPO/RLHF), and reinforcement from verifiable rewards (RLVR/GRPO) live — the techniques behind every model release you read about. You'll also learn how reasoning models trade test-time compute for accuracy, and when that trade is worth it.

18 Phase 18 · Advanced track

AI Security & Red Teaming

An agent with tools is an attack surface with a credit card attached. Prompt injection is the #1 real-world LLM vulnerability, and indirect injection — malicious instructions hiding in retrieved docs, emails, or web pages — is the version that actually bites production systems. Senior engineers threat-model first and red-team their own work before someone else does.

Difficulty · hard Advanced track Prereqs · Phases 8, 12 ≈ 1–2 weeks
0/10 ticked complete ✓

Study checklist

Defense-in-depth layers

  1. Design: no agent gets private data + untrusted content + external comms at once
  2. Tools: least privilege, read-only by default, scoped tokens, idempotent writes
  3. Runtime: sandboxed execution, network egress rules, human approval for irreversible actions
  4. Model-level: instruction hierarchy, delimiters/spotlighting, output validation
  5. Process: adversarial evals in CI, logging with redaction, incident runbooks

Practice project

  1. Threat-model your Phase 10/11 agent — one page, honest blast radius
  2. Attack it: garak scan + 20 hand-written injections (direct and via a poisoned RAG doc)
  3. Implement the top 3 mitigations; re-run the attacks; document pass rates
  4. Write it up — a red-team report is a strong portfolio artifact

¶ Reference

Quick-Reference Glossary

The terms you'll meet again and again. Bookmark this page and come back whenever a word stops making sense.

17 terms Plain-language

Core concepts

  • Transformer — the self-attention neural-network architecture underlying virtually all modern LLMs.
  • Token — the smallest unit of text a model processes (roughly a word-piece, not a full word).
  • Context window — the maximum number of tokens a model can consider at once.
  • Embedding — a numerical vector representing the meaning of text.
  • RAG — Retrieval-Augmented Generation: grounding LLM answers in retrieved external documents.

Agents & operations

  • Agent — an LLM system that reasons, acts (via tools), observes results, and repeats (the ReAct loop).
  • Agent harness — the scaffolding (tools, memory, state, guardrails) that turns a model into a working agent.
  • MCP — Model Context Protocol: the standardized way agents connect to tools and data sources.
  • LoRA / QLoRA — efficient fine-tuning techniques that adapt a model without retraining all its weights.
  • LLMOps — the operational discipline (evaluation, monitoring, deployment, versioning) of running LLM apps in production.

Advanced terms

  • Context engineering — curating everything the model sees at each step: prompts, retrieval, memory, tool output.
  • KV cache — stored attention keys/values that make token generation fast; the core of inference optimization.
  • Quantization — shrinking model weights (16-bit → 8/4-bit) to cut memory, cost, and latency.
  • DPO / RLHF — preference-based post-training methods that align models to human (or AI) feedback.
  • Test-time compute — letting models "think longer" at inference (reasoning models) instead of only scaling training.
  • Durable execution — workflow engines that persist every step so long-running agents survive crashes and retries.
  • Prompt injection — malicious instructions smuggled into model input (or retrieved content) to hijack an agent.
